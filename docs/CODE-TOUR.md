## 2. 打开首页的完整旅程（以 `localhost:3000` 为例）

1. 浏览器向 `localhost:3000` 发出请求："我要首页"；
2. Next.js 查路由表：`/` 对应 `src/app/page.tsx`；
3. `page.tsx` 是"服务端组件"——代码在服务器上先跑完，再发给浏览器；
4. 它调用 `src/lib/content-api.ts` 的 `getPublishedPosts()`（所有读内容必须走这里）；
5. `content-api.ts` 通过 `src/lib/db.ts` 拿到数据库连接，执行查询：
   **只要** `type='post'` 且 `isPublic=1` 且没进回收站的记录；
6. 查询结果（标题、摘要、日期、标签）被拼进页面骨架（`layout.tsx` 的顶栏底栏）；
7. 完整的 HTML 发回浏览器，你看见文章列表；
8. 你点进一篇文章 → 请求 `/posts/hello-world` → 走的是 `posts\[slug]\page.tsx`，
   同样的流程再走一遍，多了一步 Markdown 渲染（`components\Markdown.tsx`）；
9. 如果你点的是 `/kb`（私有区）→ 请求先被 `src/middleware.ts` 拦下：
   **没带有效登录凭证？弹回登录页。带了吗？才放行。**

### 3.2 数据层（数据长什么样、存在哪）

| 文件 | 干什么 | 一句话要点 |
|---|---|---|
| `src\db\schema.ts` | 定义四张表：`users`（站长账号）、`notes`（全部内容）、`tags`（标签）、`note_tags`（文章↔标签的关联） | **所有内容共用一张 notes 表**，用 `type` 字段区分（`post`=博客文章；日记/动态等 M3 启用）。删文章=打个时间戳（软删除），不真删 |

| `drizzle/0001_*.sql` | 第二版（加 notes/tags/note_tags） | 改表流程：改 `schema.ts` → 跑 `npm run db:generate` → 生成新记录，永不手工改库 |

### 3.3 认证层（你是怎么登录的）

| 文件 | 干什么 | 一句话要点 |
|---|---|---|

## 4. 八个"为什么"（这一节最值钱）

**① 为什么建表语句里 `datetime('now')` 要套一层括号？**
SQLite 的规矩：默认值里的函数必须写成 `DEFAULT (datetime('now'))`。我在 M0 踩过这个坑（裸写导致建表失败），括号就是那次教训留在代码里的记号。

**② 为什么 `next.config.ts` 要写 `serverExternalPackages`？**
`better-sqlite3` 的核心是编译好的二进制文件，打包器一拆它就坏。这行配置等于告诉打包器："这一个别动。"

**③ 为什么登录 Cookie 的 `secure` 暂时关着？**
`secure` 开着时浏览器只在 HTTPS 里发送 Cookie。上线初期先用 IP+HTTP 访问（域名备案期间），开着它你就永远登录不上。M5 配好 HTTPS 后打开——代码里留着注释，到时候不会忘。

**④ 为什么所有读内容都要经过 `content-api.ts`？**
两个原因：a) 它的查询条件写死了"只返回公开且未删除"，日记、私有笔记**在出口处就被挡住**，忘了写过滤也不会泄漏；b) 二期 AI 检索只需要挂在这一个文件上，不用翻改所有页面。

**⑤ 为什么测试要用独立临时数据库？**
测试会删数据、造脏数据。`BLOG_DB_PATH` 环境变量可以把数据库指到临时文件夹——测试随便折腾，真实数据一个字节都不会碰。

**⑥ 为什么删除是"软删除"？**
点删除只是盖一个时间戳，数据原封不动躺在回收站里，随时还原；只有"彻底删除"才真的清掉。防手滑，成本几乎为零。

**⑦ 为什么附件不走静态目录，而要过登录接口？**
附件可能属于私有笔记。走接口就能在出口处查登录票——没登录的人连一张图都拿不到。图片/PDF 直接预览，其他类型自动变成下载。

**⑧ 为什么版本只留最近 20 份？**
版本历史是保险，不是仓库。20 份足够"手滑救回"，数据库也不会被无限膨胀的历史撑爆。

## 7. 术语小词典

| 词 | 意思 |
|---|---|
| 路由 | 一个网址对应哪个文件，`app\` 下的文件夹名就是网址路径 |
| 服务端组件 | 代码在服务器上跑完再发给你，浏览器收到的已经是成品页面 |
| middleware | 每个请求进门之前先过的一道关卡 |
| 迁移 | 数据表结构的"变更记录本"，只追加不修改，保证任何一台机器都能从头重建一模一样的库 |
| 环境变量 | 给程序的"小纸条"（如密钥），不写在代码里 |
| 软删除 | "删除"只是盖个时间戳，数据还在——这就是回收站能还原的原因 |
