## 1. 项目概述

### 1.1 目标

在阿里云 ECS 上部署一个可长期稳定运行的个人网站(公开博客 + 私有知识库):

- 公开区:Markdown 写文章,带标签、归档、搜索、评论,SEO 友好
- 私有区:个人知识库(笔记/剪藏/日记/动态等,详见 DEVELOPMENT.md)
- 响应式 + 暗色模式,移动端体验良好
- 发布、更新走自动化流水线,不做手工运维
- 有备份,服务器炸了数据也不丢

### 1.2 非目标(第一期不做)

- 多用户 / 注册登录体系(只有博主一人)
- 手机 App
- 站内私信、社交功能
- 微信小程序
- AI 检索(定为二期,架构预留接口)

> 企业级不等于过度设计。所有组件按"一台 2核2G 服务器能长期稳定跑"来选型,同时保留清晰的分层和升级路径。

## 2. 总体架构

```
                        ┌─────────────────────────── 阿里云 ───────────────────────────┐
                        │                                                              │
 访客 ──HTTPS──> DNS(域名,备案中) ──> 安全组(仅放行 22/80/443)                      │
                        │                                      │                       │
                        │                    ┌─────────────────▼───────────────┐       │
                        │                    │  Nginx 容器                      │       │
                        │                    │  · 反向代理 / HTTPS 终止          │       │
                        │                    │  · 静态资源缓存 / gzip / 限流     │       │
                        │                    └────────────┬────────────────────┘       │
                        │                                 │ proxy_pass                 │
                        │                    ┌────────────▼────────────────────┐       │
                        │                    │  app 容器 (Next.js 全栈)         │       │
                        │                    │  · 公开区:博客(SSG/ISR)         │       │
                        │                    │  · 私有区:知识库(登录守卫)      │       │
                        │                    │  · 评论 / 点赞 API               │       │
                        │                    │  · AI 接口层(二期,留桩)         │       │
                        │                    └────────────┬────────────────────┘       │
                        │              ┌──────────────────┼───────────────┐            │
                        │    ┌─────────▼──────┐  ┌────────▼──────┐  ┌─────▼──────┐     │
                        │    │ SQLite          │  │ 附件存储卷     │  │ AI 预留     │     │
                        │    │ 全部内容        │  │ ./data/       │  │ 向量索引    │     │
                        │    └─────────────────┘  └───────────────┘  └────────────┘     │
                        │                                                              │
                        │   备份:cron 每日 dump + 附件打包 ──> OSS(对象存储)            │
                        └──────────────────────────────────────────────────────────────┘

 开发侧:本地电脑 ──git push──> GitHub 仓库(代码)
                                    │
                                    ▼
                          GitHub Actions(CI/CD)
                           · lint / build / 测试
                           · 构建镜像 ──> 阿里云 ACR 个人版(镜像仓库)
                           · SSH 到 ECS ──> docker compose pull && up -d
```

**架构要点:**

| 决策 | 说明 |
|---|---|
| 全部内容统一存 SQLite | 博客文章、笔记、日记等统一入库,才能统一做权限、搜索、备份;系统每日自动导出 Markdown 打包备份,保证数据自主权(替代早期的"文章存 Git"方案) |
| 动态数据(评论/统计)同库 | 单文件、零运维、备份就是拷文件。个人站点的并发量远不需要 MySQL/Postgres,表结构按规范设计,日后要换 Postgres 只需迁移数据 |
| 全部容器化 (Docker Compose) | 环境不可变,换服务器=拷 compose 文件重新拉起,30 分钟内可完整重建 |
| Nginx 独立一层 | HTTPS 终止、缓存、限流和应用解耦,以后加第二个服务不用动应用 |
| CI/CD 走阿里云 ACR | 镜像仓库在国内,拉取快;GitHub Actions 只做构建和触发 |
| 登录认证层 | 公私分区的前提:单管理员账号,密码哈希 + 签名 Cookie,私有区路由统一由中间件守卫 |

## 3. 技术选型

| 层 | 选型 | 备选 | 选它的理由 |
|---|---|---|---|
| 应用框架 | Next.js 15 (App Router) + TypeScript | Astro / Hexo | 博客页构建时静态生成(SSG),访问快;API 路由承载评论、笔记等功能,一个框架全包。生态最大,遇到问题最好查 |
| 样式 | Tailwind CSS | — | 不用自己维护一套 CSS,暗色模式一行配置 |
| 内容 | SQLite 统一存储 + 每日 Markdown 导出备份 | 文章存 Git | web 编辑、全文搜索、统一备份都需要入库;导出保数据自主权 |
| 数据库 | SQLite(ORM 用 Drizzle) | PostgreSQL | 零运维;并发需求用不到独立 DB 进程 |
| 认证 | 自实现单管理员会话(bcrypt + HttpOnly 签名 Cookie) | Auth.js | 一个人的系统,引入认证框架是杀鸡用牛刀 |
| 反向代理 | Nginx | Caddy | 资料最多,阿里云上证书配置文档成熟 |
| 容器 | Docker + Docker Compose | systemd 直跑 | 环境一致、可重建 |
| CI/CD | GitHub Actions + 阿里云 ACR 个人版 | Jenkins | 免费、免维护 |
| HTTPS | Let's Encrypt(certbot 自动续期) | 阿里云免费证书 | 自动化程度高 |
| 全文搜索 | 一期 LIKE 查询;二期 FTS5/Meilisearch | — | 不为第一阶段用不到的规模付复杂度 |

## 5. 数据设计(SQLite,概要)

完整表清单见 DEVELOPMENT.md 第 5 节,核心原则:

```sql
-- 评论(公开区唯一的访客写入)
CREATE TABLE comments (
  id          INTEGER PRIMARY KEY,
  post_slug   TEXT NOT NULL,
  author      TEXT NOT NULL,
  email_hash  TEXT,                    -- 只存哈希,不留明文邮箱
  content     TEXT NOT NULL,
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  is_visible  INTEGER NOT NULL DEFAULT 1   -- 软删除,站长可隐藏垃圾评论
);
```

> 设计原则:所有内容进 `notes` 主表按类型区分;用户输入一律参数化查询防注入、限制长度、XSS 过滤;私有内容绝不进公开接口。

## 6. 部署架构与服务器要求

### 6.1 服务器建议

| 项 | 要求 |
|---|---|
| 机型 | 轻量应用服务器 或 ECS,2核2G 起步,2核4G 更从容 |
| 系统镜像 | Ubuntu 22.04/24.04 LTS(选 Docker 预装镜像更省事) |
| 地域 | **待站长拍板**,见 6.2 |

### 6.2 地域与备案策略(重要决策,待拍板)

| 方案 | 优点 | 代价 |
|---|---|---|
| A. 大陆地域(如杭州/上海) | 访问速度最快 | 域名必须 ICP 备案,流程 1~3 周,需身份证实名;备案前只能用 IP 访问 |
| B. 中国香港地域 | 免备案,买完域名解析即可用 | 大陆访问延迟稍高(一般 50~100ms,做博客/知识库完全够用) |

当前默认按方案 A 规划,备案等待期先用 IP 上线运行,域名下来后解析、加 HTTPS 即可,不影响任何开发工作。嫌备案麻烦可随时切方案 B,架构不变。

### 6.3 环境划分

| 环境 | 位置 | 用途 |
|---|---|---|
| 开发环境 | 本机(Windows + Node.js) | 写代码、本地预览 |
| 生产环境 | 阿里云 ECS | 对外服务 |

> 个人项目不设独立预发布环境;风险用"镜像不可变部署 + 快速回滚"兜底:每个版本都是一个镜像 tag,回滚 = 把 compose 指回上一个 tag,30 秒完成。

## 7. CI/CD 流水线

```
git push main
   │
   ▼
GitHub Actions
   ├─ 1. 检查:ESLint + TypeScript 类型检查 + 单元测试   (~2 分钟)
   ├─ 2. 构建 Docker 镜像,tag = 短 commit hash(可回滚的版本号)
   ├─ 3. 推送到阿里云 ACR
   └─ 4. SSH 到 ECS,执行:
         docker compose pull && docker compose up -d
   │
   ▼
发布完成(从 push 到上线约 5 分钟,全程无手工操作)
```

- 发文章 = 私有区后台写完点"发布",或写笔记直接保存,其余全自动。
- 流水线里 SSH 私钥、ACR 密码等全部放 GitHub Secrets,不进代码。

## 8. 安全设计

| 层面 | 措施 |
|---|---|
| 网络边界 | 阿里云安全组仅放行 22/80/443;数据库不监听公网(容器内部网络) |
| SSH | 仅密钥登录,禁用 root 密码登录;装 fail2ban 防爆破 |
| 认证 | 单管理员;密码 bcrypt 哈希;登录接口限流;会话 Cookie HttpOnly + 签名 |
| 隐私 | 私有内容(日记/笔记)绝不进公开 API、RSS、sitemap;评论邮箱只存哈希 |
| 应用 | 评论等写接口限流(Nginx 层 10 req/min/IP);所有输入校验与 XSS 过滤;上传文件校验类型 |
| 传输 | 全站 HTTPS,HTTP 301 跳转;HSTS 头 |
| 依赖 | CI 里跑 `npm audit`,镜像用官方 slim 基础镜像 |

## 9. 备份与容灾

| 对象 | 方式 | 频率 | 保留 |
|---|---|---|---|
| 全部内容(SQLite) | cron 脚本 `sqlite3 .backup` + tar,上传阿里云 OSS;另每日导出全量 Markdown 打包 | 每日凌晨 | 30 天滚动 |
| 附件/图片 | tar 同步上传 OSS | 每日凌晨 | 30 天滚动 |
| 整机 | 阿里云控制台自动快照策略 | 每周 | 保留最近 4 份 |

**恢复演练目标:换一台全新 ECS,凭 OSS 备份 + Git 仓库 + compose 文件,30 分钟内完整恢复服务。** 上线后实际演练一次并记录到部署手册。
