## 2. 打开首页的完整旅程（以 `localhost:3000` 为例）

1. 浏览器向 `localhost:3000` 发出请求："我要首页"；
2. Next.js 查路由表：`/` 对应 `src/app/page.tsx`；
3. `page.tsx` 是"服务端组件"——代码在服务器上先跑完，再发给浏览器；
4. 它调用 `src/lib/content-api.ts` 的 `getPublishedPosts()`（所有读内容必须走这里）；
5. `content-api.ts` 通过 `src/lib/db.ts` 拿到数据库连接，执行查询：
   **只要** `type='post'` 且 `isPublic=1` 且没进回收站**且属于站长的**记录；
6. 查询结果（标题、摘要、日期、标签）被拼进页面骨架（`layout.tsx` 的顶栏底栏）；
7. 完整的 HTML 发回浏览器，你看见文章列表；
8. 你点进一篇文章 → 请求 `/posts/hello-world` → 走的是 `posts\[slug]\page.tsx`，
   同样的流程再走一遍，多了一步 Markdown 渲染（`components\Markdown.tsx`）；
9. 如果你点的是 `/kb`（私有区）→ 请求先被 `src/middleware.ts` 拦下：
   **没带有效登录凭证？弹回登录页。带了吗？才放行。**

## 3. 逐文件讲解（M0 + M1 全部文件）

### 3.1 配置层（决定项目怎么跑）

| 文件 | 干什么 | 一句话要点 |
|---|---|---|
| `package.json` | 项目清单：名字、依赖库、可用命令 | `npm run dev` 等命令都在这里定义 |
| `next.config.ts` | Next.js 的设置 | 只有一行关键配置：`better-sqlite3` 是原生模块，禁止打包器拆它（见 §4-2） |
| `vitest.config.ts` | 测试框架的设置 | 告诉测试框架 `@/` 代表 `src\`，和网页代码用同一套路径写法 |
| `drizzle.config.ts` | 数据库迁移工具的设置 | 指明表结构定义在哪、迁移文件生成到哪 |
| `.gitignore` | git 不收录的文件 | `data\`（数据库）、`.env.local`（密钥）绝不进仓库 |
| `.env.local` | 本地密钥 | 存着 `AUTH_SECRET`（登录令牌的签名密钥），只在你的电脑上存在 |

### 3.2 数据层（数据长什么样、存在哪）

| 文件 | 干什么 | 一句话要点 |
|---|---|---|
| `src\db\schema.ts` | 数据库的完整表结构（users / notes / attachments / comments / 书影音 / 书签 / 路线 / 时间线 / 打卡 / 记账 / 导航 / 好友 / 版本 / 浏览量…共 18 张） | **所有内容共用一张 notes 表**，用 `type` 字段区分（`post` 博客文章、`note` 笔记、`clip` 剪藏、`moment` 说说、`diary` 日记）。删文章=打个时间戳（软删除），不真删 |
| `src\lib\db.ts` | 打开数据库、自动执行迁移 | 全站唯一的数据库连接；启动时自动把 `drizzle\` 里的变更记录补齐到最新 |
| `drizzle\0000_*.sql` ~ `0010_*.sql` | 数据库的变更记录本 | **只追加、不许手改**。改表流程：改 `schema.ts` → 跑 `npm run db:generate` → 生成新记录（如 `0010` 给附件加归属人并回填历史数据），永不手工改库 |

### 3.3 认证层（你是怎么登录的）

| 文件 | 干什么 | 一句话要点 |
|---|---|---|
| `scripts\create-admin.ts` | 创建/重置站长账号 | 密码用 bcrypt 加密后才存库——**数据库被偷也拿不到原密码** |
| `src\app\api\auth\login\route.ts` | 登录接口 | 核对用户名+密码 → 签发一个 30 天有效的"防伪手环"（Cookie） |
| `src\lib\auth.ts` | 手环的签发与验证 | 手环 = 你的名字+过期时间，再用只有服务器知道的密钥（`AUTH_SECRET`）盖一个数学签名。**改名字？签名对不上，立刻作废** |
| `src\middleware.ts` | 私有区的保安 | 所有 `/kb` 开头的请求先过它；没带手环或手环是假的 → 弹回登录页。**唯一例外**：`/api/kb/attachments/<id>`（图片本体）放行，因为照片墙要能给访客看，公开与否由该接口自己按 `is_public` 判定 |

### 3.4 内容层（文章怎么存、怎么读）

| 文件 | 干什么 | 一句话要点 |
|---|---|---|
| `src\lib\content-api.ts` | **公开区读内容的唯一出口** | 文章列表、详情、标签云、按标签取文章、归档、最近文章、说说流、照片墙。查询条件里写死了"公开+未删除+归属站长"——隐私红线从源头兜住。**它的过滤条件 `publishedPostFilter` 同时被搜索层复用**，保证"公开"只有一个定义 |
| `src\lib\content-types.ts` | **内容类型的登记处** | `notes.type` 的合法取值（post/note/clip/moment/diary）与各自导出文件夹名，只写这一份；写入白名单和导出目录同时跟它走，加新类型不会漏登记 |
| `src\components\Markdown.tsx` | Markdown → 网页 | 支持表格/任务列表（GFM），代码自动高亮。博客文章和以后的知识库笔记共用这一个零件 |
| `scripts\seed-demo.ts` | 放入两篇示例文章 | 幂等：跑一百遍结果一样（按 slug 覆盖）。正式发布界面 M2 落地后，这个脚本就退休 |

**绘梨衣怎么"知道"站里的事**:每次对话,服务端会把站点信息+最近 10 篇文章(标题/日期/摘要)注入系统提示词,所以她能介绍站内内容并推荐文章;换壁纸、改歌单她下次也会"知道"。

**外观系统怎么运作**:外观设置存数据库表 `site_settings`,页面每次渲染都读它——所以在后台换背景图、拖虚化滑杆,首页刷新就变,不用碰任何代码。`site-config.ts` 里的静态值只是"没设置时的默认值",保证永远有图可用。

**沉浸式壁纸(M3 二轮打磨)**:整站背景 = 壁纸图(layout 里 fixed 铺满 + 可调虚化 + 主题色遮罩),所有玻璃卡片浮在它上面——玻璃"透"的是真实的图。壁纸默认跟随 Hero 背景图,也可在外观设置里单独指定;首页小部件区用负边距上浮压住 Hero 底边(参考站标志构图);"在线访客"由页面心跳(45 秒/次)上报,5 分钟内报过到的算在线,单实例内存口径。

### 3.10 全站体检修复(2026-09-28)

一次只读体检暴露出来的问题,按"看起来最明显 → 数据最要紧"的顺序修完:

| 位置 | 修了什么 | 一句话要点 |

## 4. 十五个"为什么"（这一节最值钱）

**① 为什么建表语句里 `datetime('now')` 要套一层括号？**
SQLite 的规矩：默认值里的函数必须写成 `DEFAULT (datetime('now'))`。我在 M0 踩过这个坑（裸写导致建表失败），括号就是那次教训留在代码里的记号。

**② 为什么 `next.config.ts` 要写 `serverExternalPackages`？**
`better-sqlite3` 的核心是编译好的二进制文件，打包器一拆它就坏。这行配置等于告诉打包器："这一个别动。"

**③ 为什么登录 Cookie 的 `secure` 暂时关着？**
`secure` 开着时浏览器只在 HTTPS 里发送 Cookie。上线初期先用 IP+HTTP 访问（域名备案期间），开着它你就永远登录不上。M5 配好 HTTPS 后打开——代码里留着注释，到时候不会忘。

**④ 为什么所有读内容都要经过 `content-api.ts`？**
两个原因：a) 它的查询条件写死了"只返回公开且未删除"，日记、私有笔记**在出口处就被挡住**，忘了写过滤也不会泄漏；b) 二期 AI 检索只需要挂在这一个文件上，不用翻改所有页面。

**⑤ 为什么测试要用独立临时数据库？**
测试会删数据、造脏数据。`BLOG_DB_PATH` 环境变量可以把数据库指到临时文件夹——测试随便折腾，真实数据一个字节都不会碰。

**⑥ 为什么删除是"软删除"？**
点删除只是盖一个时间戳，数据原封不动躺在回收站里，随时还原；只有"彻底删除"才真的清掉。防手滑，成本几乎为零。

**⑦ 为什么附件不走静态目录，而要过接口？**
因为同一个地址要同时服务两种东西：照片墙、说说配图、站点背景图这些**公开**文件访客必须能看；私有笔记里的附件又绝不能外流。走接口就能在出口处分别判定——标了公开的直接给，没标的要登录、还得证明是自己传的。图片/PDF 直接预览，其他类型自动变成下载。

**⑧ 为什么版本只留最近 20 份？**
版本历史是保险，不是仓库。20 份足够"手滑救回"，数据库也不会被无限膨胀的历史撑爆。

**⑨ 为什么保安（middleware）要对图片地址单独放行？**
保安只认"有没有登录"，不认"这张图是不是公开的"。而图片地址正好在 `/api/kb/` 底下会被一并拦下——症状就是访客打开照片墙全是裂图。与其在保安那儿再写一套"哪些附件算公开"的规则（等于同一件事写两份，早晚走岔），不如放行到图片接口，由它一处判定。

**⑩ 为什么"我的内容"只定义在两个出口里，不让各页面自己写？**
站点升级成多用户之后，"这条数据是不是我的"这个判断出现在搜索、图谱、周报、导出、统计等六七个地方。各写各的，漏掉一处就是一个越权读取（本次体检抓到的正是这种）。现在它只有两个定义：公开区的 `publishedPostFilter`、私有区的 `kbOwnerFilter`，其它模块一律复用它俩。

**⑪ 为什么首页首屏不单独存一张图，而是跟着壁纸走？**
因为"首屏该放什么"只有一个正确答案：你选的那张壁纸。以前 Hero 有自己的一套图源，结果顶部挂着系统自带的占位插画，你精心挑的绘梨衣被压在所有卡片最底层——两处设置各说各话，看起来就像两张皮。现在的顺序是：单独设过 Hero 图就用它 → 否则用壁纸 → 都没有才用内置插画。墙纸一换，首屏跟着换。

**⑫ 为什么首页侧栏撤掉了音乐卡？**
侧栏要能"滚到底就停住"（吸附），前提是它得比视口矮——比视口高的东西一旦钉在顶部，底下那截就永远露不出来。而侧栏里那张音乐卡和左下角的浮动圆盘其实是同一个播放器的两份皮（浮动圆盘每页都在，播放/暂停/自动下一首都有）。两相权衡，留下每页都有的那个，撤掉重复的卡片，侧栏正好装得下。
顺带一提，吸附用的 `max-h` + `overflow-y-auto` 是防呆：万一以后又往侧栏加卡片（比如打开恋爱卡），超出部分会在栏内滚动，而不是被悄悄切掉。

**⑬ 为什么侧栏的卡片总在互相挤来挤去？**
因为侧栏要能"滚到底就停住"（吸附），前提是它得比视口矮。所以每一栏的内容高度其实是有预算的：资料卡约 362 + 公告 86 + 音乐 217 ≈ 697，而可用高度约 812。文章页要在右栏放"文章目录"，就只能把"站点统计"让出去——否则多出来的部分要么被切掉，要么冒出内部滚动条。这不是抠门，是这条布局规则推出来的硬约束：**先想清楚这一栏能装下多少，再决定放什么。**

**⑭ 为什么知识库问答不走向量检索？**
几十篇的量级下，关键词打分在浏览器里算完是零延迟的，而且**能解释"为什么选中这篇"**；向量检索在这个量级上既慢，又要多一套索引、一个嵌入模型和一份依赖。真正要守的底线是另一条：**得 0 分的笔记一律不发给模型**，宁可老实回答"知识库里没有"，也不拿不相关的内容去凑答案。
顺带一个中文的坑：中文没有空格，如果按标点切词，"我该怎么部署"整句会变成一个词，永远匹配不上——所以中文段落要按 2-gram 切（这个 bug 是写测试时抓出来的，不然问答功能等于废的）。哪天笔记上千了，要换的也只是 `lib/retrieval.ts` 这一个函数。

**⑮ 为什么工作台要自己挂一个 `dark` 类？**
因为星系背景必须是暗的，而站点主题是可以切换的——总不能站长一切到浅色模式，星空就变成一片白。挂上 `dark` 之后，里面所有 `glass` 卡片、边框、`dark:` 变体都自动走深色那套，等于用一行类名把整个子系统"锁定"在夜间模式，不用给每个组件重写一遍暗色样式。
这里踩过一个坑：光挂 `dark` 文字还是黑的。原因是 `color` 在 `body` 上就按浅色算好并继承下来了，**覆盖子树的 CSS 变量不会反推已经继承下来的 `color`**——所以还要在容器上显式写一次 `text-foreground` 让它重新取值。同理，canvas 里画图要用主题色时，得从"画布所在的容器"读变量，不能从 `<html>` 读。

## 7. 术语小词典

| 词 | 意思 |
|---|---|
| 路由 | 一个网址对应哪个文件，`app\` 下的文件夹名就是网址路径 |
| 服务端组件 | 代码在服务器上跑完再发给你，浏览器收到的已经是成品页面 |
| middleware | 每个请求进门之前先过的一道关卡 |
| 迁移 | 数据表结构的"变更记录本"，只追加不修改，保证任何一台机器都能从头重建一模一样的库 |
| 环境变量 | 给程序的"小纸条"（如密钥），不写在代码里 |
| 软删除 | "删除"只是盖个时间戳，数据还在——这就是回收站能还原的原因 |
