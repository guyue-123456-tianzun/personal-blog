## 1. 项目定义

**一句话**:一个属于你自己的个人网站,公开面是博客,登录后是你的私人第二大脑;二期加上 AI,能对你自己的笔记提问。

### 1.1 已确认的关键决策

| # | 决策 | 结论 | 依据 |
|---|---|---|---|
| D1 | 博客和知识库的关系 | **合一**:一套系统,公开区(博客)+ 私有区(知识库) | 一次部署、一个域名、一套运维;还没写代码,合并零成本 |
| D2 | 实现形态 | **代码自建**(Next.js 全栈) | 完全按需求定制、技术栈统一、AI 可深度集成 |
| D3 | AI 能力 | **一期不做,架构预留**;二期做语义检索 + RAG 问答 | 先把地基打牢 |
| D4 | 部署 | 阿里云 ECS + Docker(沿用 ARCHITECTURE.md) | 已有明确的服务器计划 |
| D5 | 补充模块 C 区 | **C1~C10 全部纳入一期**(2026-09-27 确认) | 你拍板全选 |
| D6 | 视觉方向 | **二次元玻璃拟态风**:全屏 Hero 大图 + 个性签名、半透明卡片、站点数据/音乐播放器/日历等小部件、文章封面卡、深浅色手动切换(2026-09-27 依你提供的 6 张参考图综合定稿) | 参考站的技术栈(FastAPI/Astro/Typecho)不采用,只取设计 |

### 1.2 关于"我不会 Next.js 怎么办"

**你不需要会。** 这个项目的分工是:

| 谁 | 做什么 | 需要的能力 |
|---|---|---|
| 我 | 全部编码、部署、排错 | — |
| 你 | 用浏览器验收、提需求、选模块 | 会用浏览器即可 |

你实际要做的事只有三类:
1. **验收**:每个里程碑我给你网址(先是本机 localhost,后是服务器 IP),你打开点点看,提意见;
2. **决策**:选模块、起站名、买服务器/域名这类只有你能拍板的事;
3. **执行身份操作**:注册 GitHub、买域名、本人实名备案(法律要求必须本人)。

可选加分项(完全自愿):想学的话,这个项目本身就是最好的教材——代码注释保持完整,随时指着任何一行问"这是干嘛的"。不想学也完全不影响项目推进。

项目根目录的 `AGENTS.md` 记录技术栈、规范和进度,任何 AI 助手接手前都会先读它——哪怕换一个 AI、甚至换成人类开发者,都能无缝接手。

## 2. 需求清单

### 2.1 权限模型(全系统的地基)

| 角色 | 能做什么 |
|---|---|
| 游客 | 只能看公开区:已发布的博客文章、关于页;能发评论 |
| 站长(你) | 登录后进入私有区,拥有一切:写笔记、看日记、管内容 |

- 单管理员账号(就你一个),用户名 + 密码登录,密码哈希存储,登录接口限流防爆破
- 私有区所有路由由中间件统一守卫,未登录一律跳登录页
- **隐私红线:日记、笔记等私有内容不出现在任何公开接口、RSS、sitemap 里**

### 2.2 A 区:公开博客

| 模块 | 说明 | 验收标准 |
|---|---|---|
| 文章发布 | 站长在后台写 Markdown,一键发布到公开区 | 发布后游客立即可见;未发布的游客不可见 |
| 文章列表/详情 | 首页时间线 + 文章页,代码高亮 | 手机浏览器显示正常 |
| 标签/归档 | 按标签、按年月浏览 | 每篇文章可打多标签 |
| RSS 订阅 | 输出 RSS feed | RSS 阅读器可订阅,只含公开内容 |
| SEO | meta 标签、sitemap、Open Graph | Google/百度可收录 |
| 评论 | 游客留言,站长后台可见可删 | 支持匿名昵称;垃圾评论可隐藏 |
| 关于页 | 个人介绍(内容你提供) | — |

### 2.3 B 区:私有知识库(已确认的 8 类内容)

> 设计原则:**所有内容类型共用一套"笔记"底座**(Markdown 正文 + 标签 + 搜索 + 附件),每种类型只是底座上的一个视图。这样加新类型成本低,搜索和 AI 二期只需对接一处。

| 模块 | 用法 | 关键功能 | 验收标准 |
|---|---|---|---|
| B1 技术学习笔记 | 代码片段、命令、踩坑 | Markdown 编辑器、代码高亮、`[[双向链接]]`、标签 | 手机上也能看能改;搜索能搜到正文关键词 |
| B2 网页剪藏 | 存档好文章 | 粘贴 URL → 服务端自动抓取正文存为笔记(存 Markdown 副本,防原文失效) | 剪藏后的文章离线可读、可搜索;二期再做浏览器一键插件 |
| B3 想法速记 | 碎片灵感随手记 | 手机端"快速记录"入口:打开即输入框,一键保存,不用排版 | 从掏出手机到记完 ≤ 15 秒 |
| B4 朋友圈式动态 | 个人时间线 | 短动态 + 配图,按时间刷;**可选择某条是否同步公开到博客** | 发图、删除、公私切换都可用 |
| B5 日记 | 每日一篇 | 日历视图逐日浏览;严格私有(见隐私红线) | 任何一天点进去能看到当天日记;游客绝不可访问 |
| B6 文档/资料附件 | PDF、电子书、截图 | 上传、预览(PDF/图片)、和任意笔记关联 | 附件可从笔记内打开;总容量统计可见 |
| B7 个人学习路线 | 成长规划 | 路线 → 阶段节点 → 逐个打卡完成,进度条可视化 | 能看到"完成 3/10 节点"这类进度 |
| B8 成长经历时间线 | 大事记 | 时间轴页面,记录重要节点,可关联相关笔记 | 按年月展示,支持增删改 |

### 2.5 明确不做(负面清单)

- 存密码、证件、银行卡等敏感信息——自建系统的安全强度扛不住这种泄露后果
- 多用户、注册、社交(好友/关注)——这是你一个人的系统
- 微信小程序、App——响应式网页已覆盖手机场景
- 一期 AI(已定二期,接口预留)

### 2.6 非功能需求

| 维度 | 要求 |
|---|---|
| 安全 | 私有区全部走登录态;上传文件校验类型;所有输入防注入/XSS;登录限流 |
| 备份 | 数据库每日自动备份到 OSS;附件同步备份;全部内容可 C8 导出 |
| 性能 | 博客公开页静态化,秒开;私有页单用户场景无需优化 |
| 数据自主权 | 内容格式就是标准 Markdown,随时可整个带走,不锁定在任何工具里 |
| 代码质量 | 架构按 AGENTS.md 分层;关键代码中文注释说明含义;`docs/CODE-TOUR.md` 随里程碑更新;**核心模块必须带 Vitest 功能测试,`npm run test` 全绿才交验收**(2026-09-27 站长要求) |

### 3.1 与博客期架构的差异(决策记录)

| 变更 | 原方案 | 现方案 | 理由 |
|---|---|---|---|
| 内容存储 | 博客文章存 Git 文件,评论存 SQLite | **全部内容统一存 SQLite**,系统每日自动导出 Markdown 打包备份 | 合并后内容类型多(笔记/日记/动态…),入库才能统一搜索、统一权限、统一备份;web 编辑场景下"内容即代码"反而是绕路 |
| 新增 | — | 登录认证层(单管理员) | 公私分区的前提 |
| 新增 | — | 附件存储卷 + 上传管理 | B6/B4/C6 的地基 |
| 新增 | — | AI 接口层桩(统一的内容读取接口) | 二期 RAG 时不需要重构,直接在接口层接向量检索 |
| 变更 | 编辑器用 Milkdown 所见即所得 | **M2 落地为双栏 Markdown 编辑器**(左写右实时预览,移动端切换),Milkdown 列为可选升级 | 所见即所得编辑器体积大、与 React 19 兼容风险高;双栏体验已覆盖需求 |
| 变更 | 附件经 Nginx 静态目录直出 | **附件走鉴权接口输出** | 附件可能属于私有笔记,过登录校验更安全;公开图床需求出现后再开白名单目录 |

## 4. 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | Next.js 15 + TypeScript + Tailwind | 博客页静态生成秒开,API 路由承载全部功能,生态最大 |
| 认证 | 自实现单管理员会话(密码 bcrypt 哈希 + HttpOnly 签名 Cookie) | 一个人的系统,引入 Auth.js 属于杀鸡用牛刀 |
| 编辑器 | Milkdown(所见即所得的 Markdown)+ 移动端纯文本快速模式 | B3 速记需要"打开就能打字" |
| 剪藏解析 | Mozilla Readability(服务端抓取正文) | 业界标准,Firefox 阅读模式同款 |
| 全文搜索 | 一期:SQLite `LIKE` 查询(个人量级几千条完全够);二期:SQLite FTS5 或 Meilisearch | 不为第一阶段用不到的规模付复杂度 |
| 数据库 | SQLite + Drizzle ORM | 单文件、零运维、备份即拷贝 |
| AI 预留 | 内容读取统一走 `lib/content-api`,二期在此挂向量检索(sqlite-vec)+ 大模型 API | 保证二期不重构 |

## 5. 数据设计(概要)

```
users            站长账号(id, 用户名, 密码哈希)
notes            所有内容的主表(id, 类型[note|clip|moment|diary], 标题, Markdown正文,
                 是否公开, 置顶, 创建/更新/删除时间 —— 回收站用软删除)
tags / note_tags 标签体系(多对多)
clips            剪藏扩展(url, 站点名, 抓取时间)
attachments      附件(id, 关联笔记可空, 文件名, 类型, 大小, 存储路径)
learning_paths   学习路线(id, 标题, 描述)
path_nodes       路线节点(关联路线, 标题, 完成状态, 排序)
timeline_events  成长大事记(日期, 标题, 正文, 可关联笔记)
media_items      书影游记录(C1:类型, 状态, 评分, 短评)
bookmarks        书签(C2:网址, 标题, 摘要)
goals / checks   目标与习惯打卡(C3)
finance_records  记账(C9:金额, 分类, 时间, 备注)
comments         博客评论(公开区)
post_views       浏览计数
```

> 详表结构(DLL)在 M0/M2 落地时以 Drizzle 迁移脚本为准,本节是设计概要。

## 7. 人机协作规范

1. **目标 + 验收标准驱动**:每个任务以 2.2~2.4 的验收标准为完成定义,不靠感觉;
2. **先方案后动手**:进入新里程碑前,先给实现方案再写码(方案已在本文档中的除外);
3. **交付前自验**:每个里程碑先自己跑通验收标准,才请你验收;
4. **一会话一主题**:修 bug 的会话不顺带重构;
5. **偏差即停**:你发现方向不对,当场说,立刻纠正;
6. **AGENTS.md 承载项目记忆**:技术栈、规范、进度都在里面。
